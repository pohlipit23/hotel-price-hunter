## Prepared checks

`scripts/verify-private-cloud.mjs` defaults to an offline prerequisites description. `--self-test` tests origin validation, output sanitisation and strict OCI lineage without gcloud, network access or generation. Live execution validates the fixed project number/ID, explicit canonical URL and exact Ready/traffic revision. For the image, it requires the service input to name the approved immutable index, fetches that exact index from the official registry with an in-memory CLI access token, verifies the raw body SHA-256, and requires its sole Linux/amd64 manifest descriptor to match the revision spec and resolved digest. Only an optional unknown/unknown attestation linked to that same child is accepted; wrong body/child/architecture/attestation rejects. Invoker IAM remains enabled and broad invocation principals absent. It reads exact app origin/model/environment, runtime account, direct project grants/custom inference role, reviewed scaling/CPU/memory/concurrency/timeout limits, and current Firestore native/Standard/Singapore/delete-protected metadata. Inherited project authority is not exhaustively audited by its direct-binding check; independent gate review remains separate.

Private application checks use a CLI identity token captured in process memory. No token is logged, written to a file, included in a URL or taken from browser credentials. Two synthetic visitors receive separate app cookies/CSRF tokens, also kept in memory. Checks cover:

- Anonymous root HTTP 403; authenticated HTML, `/booking.css` and `/booking.js` HTTP 200 with SHA-256 hashes derived from **approved `9c98ede` Git snapshot assets**, normalising only Windows CRLF to Git LF, health and allowlisted bootstrap HTTP 200, with health `storage=firestore`. Active unreviewed main-branch UI/assets are not the deployment expectation; no other source rewrite is accepted.
- Missing separate confirmation, wrong origin and wrong CSRF rejection; current-version enrolment produces a separately bound permission record.
- Selected comparison and preferences restored through a refresh; the second visitor remains unenrolled and unselected.
- A read-only Firestore document lookup for the exact newly created synthetic visitor proves its enrolled/selected state exists in the actual database. Document IDs and session/CSRF fields are never retained in evidence.
- Current-version revocation succeeds; replay of the earlier affirmative intent returns HTTP 409 and authority stays false after refresh.
- When separately authorised, exactly one application `/api/advice` request per equivalent refund, uncertain-plan non-refundable offer, and unknown-essential-condition question. The verifier does not call a model directly, make an extra health generation or retry.

The model adapter inspected in the application sets `maxOutputTokens=800`, provider retry attempts `1` and a 20-second timeout. The verifier preserves safe application advice JSON, question, offer ID, HTTP status, model/location configuration and attempt number. Deterministic decision fields and basic scenario checks are recorded; the coordinator must read the complete prose before recording a semantic verdict. Provider error details, identity tokens, operator identity and cookie/CSRF data are excluded.

```text

```

The coordinator first grants `--calls=0` baseline verification, then separately grants three model attempts only after all baseline rows pass. `--calls=0` performs no advice request. Flags record an existing coordinator/human instruction; they never create authority. Identity/metadata failures stop dependent checks. `C:/Users/pohli/Sites/hotel-price-hunter/.local/private-cloud-result.json` retains current sanitised evidence; separate `private-cloud-baseline.json` and `private-cloud-model-result.json` files preserve baseline and model-phase proof. The fixed **global main-workspace** path `C:/Users/pohli/Sites/hotel-price-hunter/.local/private-cloud-model-budget.json` is created exclusively only after prerequisite/application checks pass and reserves each attempt **before** its request, preventing accidental rerun/reset of the same budget even if the verifier is copied or run from another checkout. A pre-call failure still requires coordinator review before any rerun; no worker silently removes/resets the budget file. Root also tracks the global total across all workers.

This is private service HTTP/data verification, **not browser visual QA** or a public deployment. The HTML/style checks prove the deployed asset route, while layout/accessibility evidence remains a separate browser check. A successful health response alone does not prove actual model availability or Firestore enrolment durability; those have independent rows.

Official authentication basis: [Cloud Run developer private-service authentication](https://docs.cloud.google.com/run/docs/authenticating/developers), [Artifact Registry access-token password authentication](https://docs.cloud.google.com/artifact-registry/docs/docker/authentication). The private app uses the documented CLI identity-token header flow only when the caller has invocation permission. Registry auth uses short-lived access-token password authentication in memory, never a Docker config write. This verifier grants none. Cloud health verification uses `/health`; `/healthz` is reserved by the Google frontend and cannot serve as the Cloud Run app evidence endpoint.
