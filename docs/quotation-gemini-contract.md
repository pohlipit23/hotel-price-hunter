# Restore Gemini to the hackathon customer path

17 October 2026. The original agreed plan requires live Gemini preference understanding and grounded offer advice. The quotation-backed demo replaced the original customer server and lost this integration. Restore it in the selected-room review while preserving the current three-step UI and selection-only confirmation.

Current model decision: **Gemini 3.8 Flash**, `gemini-3.8-flash` / `global`, with LOW thinking and no sampling overrides. The human-authorised three-request evaluation passed; its new 3/3 allowance is now exhausted. See [live results and release boundary](gemini-38-evaluation.md). This supersedes the earlier proposed 3.1 Flash-Lite evaluation target.

The traveller asks a question about the selected option with its facts still visible. Gemini interprets their priority (price, flexibility, room details or a balanced comparison), recommends keeping the quotation or considering the option, and selects relevant grounded reasons. Follow-up questions include a bounded previous exchange for that option. Advice never checks acknowledgements or confirms a selection.

Only allowlisted display facts reach Vertex AI: hotel/room labels, dates and occupancy counts, quotation retail total, converted source estimate, cancellation flags, capture timestamp and comparison limits. Exclude quotation codes, guest data, supplier identifiers, tokens and private references. Questions are limited to 1,200 characters; the UI asks travellers to omit personal information. Model output contains only validated enums/reason codes. Application-owned text explains amounts, incomplete terms, source estimates and the absence of any booked stay or refund. No future-price prediction or room-equivalence inference is allowed.

Use the pinned Google Gen AI SDK and Vertex AI's structured output. Configuration requires explicit `QUOTATION_ADVICE_ENABLED=true` plus project, location and model. No generation at startup, page load or option selection. Requests require the existing session, canonical origin, CSRF token, selected option and exact snapshot version. Limit each visitor to four requests per minute and each server instance to twenty, with at most two outstanding requests. No automatic provider retries; a twenty-second timeout leaves the quotation/selection intact. These instance-local guards are abuse limits, not a deployment-wide spending cap.

Keep the original fictional-booking advisor and its historical inference ledgers unchanged. Local tests use injected providers, visibly labelled as test responses. Live testing requires a new bounded call allowance because the earlier five-call allowance is exhausted. Deployment is separate approval: the current public service needs a reviewed image with SDK dependencies and the explicit feature/model configuration. No new access grant, supplier call, booking action, email or agency/watch change is included.

Acceptance: grounded price/flexibility/room questions; unknown terms; strict output validation and injection resistance; private-field exclusion; no confirmation side effects; snapshot/session/CSRF/rate/concurrency guards; timeout/provider failure; stale client response isolation; keyboard and responsive review; production image packaging. Live semantic acceptance remains distinct from injected tests.

Sources: [Google Gen AI structured output example](https://github.com/googleapis/js-genai/blob/main/sdk-samples/generate_content_with_response_schema_accept_json_schema.ts), [SDK generation configuration](https://googleapis.github.io/js-genai/release_docs/interfaces/types.GenerateContentConfig.html).
