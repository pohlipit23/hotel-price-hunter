## Resolved findings

1. **Resolved P1 — Stale preference requests could restore revoked permission.** Original app/server.mjs:165-173 ignored the submitted preference version, assigning current+1, and did not bind separate confirmation to the source version. The original independent repro enabled v1 -> v2, revoked v2 -> v3, then replayed the old v1 enable request -> HTTP 200/v4/standing authority. Current app/server.mjs:167-177 validates both preferences.version and permissionConfirmation.preferenceVersion against the transaction's current version and rejects stale values with 409 PREFERENCES_VERSION_CHANGED. The saved record retains sourcePreferenceVersion and binds the newly saved preferenceVersion. Independent recheck against the updated running localhost:8080 server: legitimate enable 200, current-version revoke 200, exact original payload replay 409; refreshed state remains v3, automaticEquivalentSwitches false, permissionRecord null and offer authority null. With two fresh Firestore clients and two independent local servers, concurrent intents using one source version produced [200,409] and advanced exactly once. A current preferences body carrying the earlier separate confirmation also returned 409. README documents the source binding, conflict response and explicit reload/reconfirmation.

2. **Resolved P2 — Gemini lacked the verified refund breakdown.** Original app/gemini.mjs:62-70 stripped refundQuote, supplying the USD 55 saving without the USD 60 price difference/USD 5 fee explanation. Current app/gemini.mjs:22-34 and :80 provide a scalar allowlist of quote status/basis, bound retail amounts, cancellation/switch/refund-processing costs, net saving, currency and bounded safe source. Independent injected-generator capture matches the fixture quote exactly: 60000 original, 54000 replacement, 0 cancellation, 500 switch fee, 0 processing, 5500 net, USD, fictional policy source. applicationDecision.netSavingMinor stays 5500. Raw identity, supplierCost and an injected nested quote extra/token do not enter the request; no tools or live model request occurred. README accurately documents this grounding.
