Current `scripts/prepare-cloud.ps1:67` checks matching account metadata, enabled status, exactly the two allowed direct project roles without conditional bindings, and the exact GA/non-deleted two-permission custom role. 2. **Resolved P1 — Existing secret environment or mounts could survive deployment.** In the installed Google Cloud CLI, literal environment changes and secret environment changes are separate transformations; `--set-env-vars` alone is insufficient evidence that credentials have been removed. Current `scripts/prepare-cloud.ps1:110` rejects extra containers, volumes/mounts, secret `valueFrom`, forbidden/unknown variables, and validates the complete five-value literal production environment after origin configuration and before publication. Offline secret-ADC/mount fixtures stop before deployment reuse or public IAM mutation. Existing production exact-origin/CSRF application code is unchanged. [Deployment environment and secret flags](https://docs.cloud.google.com/sdk/gcloud/reference/run/deploy).

3. **Resolved P2 — Database reuse did not enforce the proposed edition/protection.** Earlier reuse checked only Native mode and Singapore. Current `scripts/prepare-cloud.ps1:222` also requires explicit `STANDARD` and `DELETE_PROTECTION_ENABLED`; missing metadata stops rather than being treated as proof. The independent Enterprise/Singapore/Native fixture is rejected before repository creation. Location and edition are not silently changed. [Firestore database resource fields](https://docs.cloud.google.com/firestore/docs/reference/rest/v1/projects.databases).
